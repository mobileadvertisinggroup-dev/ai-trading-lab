ONE READ-ONLY COMMAND — safe execution-host check (D76 item 7)

Paste this single command into Terminal on your Mac and send back the
output. It only READS system facts (no writes, no network, no key
access, no installs) and prints a RECOMMENDATION line mapping your
hardware to the options in readiness/MAC_LOCAL_EXECUTION_PLAN.md.

/bin/bash -c 'echo "== MODEL ==" ; sysctl -n hw.model 2>/dev/null; sysctl -n machdep.cpu.brand_string 2>/dev/null; uname -m; sw_vers 2>/dev/null | tr "\n" " "; echo; echo "== MEMORY =="; RAM=$(sysctl -n hw.memsize); echo "MemTotal_bytes=$RAM (~$((RAM/1073741824)) GiB)"; vm_stat | awk "/free|inactive|wired/ {print}"; echo "== HOST SWAP (must be ZERO used for any VM option) =="; sysctl vm.swapusage; ls -la /private/var/vm/ 2>/dev/null; echo "== HIBERNATION / SLEEPIMAGE =="; pmset -g | grep -E "hibernatemode|standby" ; echo "== FILEVAULT =="; fdesetup status 2>/dev/null; echo "== VIRTUALIZATION SUPPORT =="; sysctl -n kern.hv_support 2>/dev/null | sed "s/^1$/hypervisor_supported=yes/;s/^0$/hypervisor_supported=no/"; echo "== DISK =="; df -h / | tail -1; echo "== RECOMMENDATION (per the D78-revised plan) =="; if [ "$RAM" -ge 51539607552 ]; then echo "VM option CONDITIONALLY possible: >=48 GiB RAM gives host+locked-guest headroom — BUT it still requires mechanical proof of host-swap-zero, wired (non-pageable) guest RAM, hibernation/dumps off, and a full-size in-VM rehearsal, per the plan. Option A (dedicated Linux >=32 GiB) remains the recommended path."; elif [ "$RAM" -ge 34359738368 ]; then echo "VM option MARGINAL at 32-48 GiB: locked-guest + host headroom is tight; every host-persistence property must still be proven. RECOMMENDED: Option A — dedicated local Linux hardware >=32 GiB, swap disabled, key entered locally."; else echo "VM option NOT viable on this Mac (<32 GiB for host+locked guest). RECOMMENDED: Option A — dedicated local Linux hardware >=32 GiB (swap disabled, no hibernation/core dumps, key entered locally); otherwise Option B (formally amended native-macOS design, independently dress-rehearsed) or Option C (keep the holdout sealed)."; fi'

What the fields mean (D78-corrected):
- MemTotal governs headroom: the guest needs ~21 GB by the frozen 1.5x
  margin, and for a VM the guest RAM must be LOCKED (non-pageable) on
  the host — so the Mac needs host+guest headroom (realistically
  ≥ 48 GiB) on top of every other proof.
- vm.swapusage is a HARD criterion for any VM option: disabling swap
  inside the Linux guest does NOT stop macOS from paging VM-process
  memory; host swap used must be mechanically zero before/during/after,
  with guest RAM proven wired on the host.
- FileVault (encrypted swap) is NOT automatically sufficient under the
  frozen no-plaintext-persistence policy; accepting it would be a
  formal amendment for your explicit adjudication.
- hibernatemode must be 0 with no sleepimage; core dumps, VM
  snapshots, and suspend/save-state must never be used (they write
  guest RAM to disk).
- kern.hv_support=yes only means a VM CAN run — it proves none of the
  persistence properties above.

Nothing in this command touches your age key, and no option ever
involves entering the key on a project-controlled remote host.
